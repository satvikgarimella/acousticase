# Arjun's integration handoff

Satvik's backend runs at `http://127.0.0.1:8000`. Interactive docs: `/docs`; machine-readable schema: `/openapi.json`. This URL refers to the computer running the browser: on a different laptop you need to run the backend there or arrange a reachable shared server. No shared server has been deployed.

## Integration sequence

1. POST multipart form to `/analyses` with `file` and `options` (a JSON string, not a separate JSON request body).
2. Read `analysis_id`; poll `/analyses/{id}` approximately once per second. Stop polling on `complete` or `failed`.
3. On completion, GET `/analyses/{id}/results`.
4. Resolve `assets.*` against the backend origin. Use `audio_url` for playback: it is aligned with all event/chart timestamps.
5. Click a finding -> resolve its `evidence_ids` -> seek to the selected event's `start_s`, highlight `[start_s, end_s]`, and show measurements/explanation. Use `peak_s` for its timeline marker.

```javascript
const form = new FormData();
form.append('file', selectedFile);
form.append('options', JSON.stringify({
  tracking_start_s: 0,
  frequency_min_hz: 80,
  frequency_max_hz: 1500,
  assume_constant_tone: false,
  assume_stationary_microphone: false,
  is_simulated: false,
  use_classifier: true
}));
const response = await fetch(`${API}/analyses`, { method: 'POST', body: form });
if (!response.ok) throw new Error(JSON.stringify(await response.json()));
const job = await response.json();
```

Do not manually set `Content-Type` for FormData; the browser supplies the multipart boundary. `POST` returns 202 even for a cached completed result. Check the `status` field immediately.

## Visuals

- Waveform JSON contains `start_s`, `end_s`, `min`, `max` arrays, in digital sample amplitude, not calibrated sound pressure.
- Spectrogram is a labeled PNG spanning the full recording, 0–4000 Hz. Use the track JSON to build an interactive frequency-time chart separately.
- Track JSON contains `time_s`, `frequency_hz`, `local_contrast_db`, and `supported` arrays. A track is a candidate spectral ridge, not a confirmed vehicle trajectory.
- Pipeline 0.2.0 adds optional `assets.sound_scores_url` when classification succeeds. The JSON has parallel `start_s`/`end_s` arrays and `groups[]` containing `key`, `label`, `onset_threshold`, and `scores`. Use this for an optional score chart; scores are not probabilities. The asset is absent when classification is disabled or fails.
- Sound events consolidate related labels. Use `measurements.sound_group` for grouping/color: horn, siren, engine, tire_squeal, glass, impact, vehicle, speech, footsteps, dog, rain, wind. `source_labels` retains underlying YAMNet labels and scores. Existing event IDs, finding references, and click-to-evidence behavior remain compatible.
- `motion.fit.time_s` and `predicted_frequency_hz` provide the model overlay. Label rejected fits as rejected. `motion.reasons` explains the outcome.

## Display rules

- Show `recording.is_simulated` prominently. It is provided by the uploader, not automatically detected.
- Use different labels for `measurement`, `model_suggestion`, and `conditional_inference`.
- Render null speed as “Insufficient evidence” or “Assumptions required”, depending on status. Never turn null into zero.
- `model_score`, `support_fraction`, and `rmse_hz` are different diagnostics. Do not call any of them “confidence” or a percentage likelihood of a collision.
- The two motion assumptions should be explicit controls. A user should not accidentally assert them by clicking Analyze.
- The source sound is not necessarily a vehicle. A transient does not establish a collision.
- Show warnings/limitations. Reports use structured findings, with no runtime LLM dependency.
- Preserve timestamps: the current UI audio origin is zero; original video alignment needs the offset supplied by the backend.

## Error states

400 empty upload; 413 file too large; 422 invalid options; 429 queue full; 404 unknown job/asset; 409 results/assets requested before completion. Decode errors and over-duration clips are reported as a `failed` job with `error` text.

## Development assets

`backend/examples/simulated-pass-by.wav` has explicit synthetic ground truth in its neighboring JSON file. `backend/examples/example-result.json` and `backend/examples/example-status.json` are generated by the same backend for mock development. Their URLs reference an analysis ID and require the live backend/assets; the JSON alone does not bundle served URLs.

Use the checked-in `backend/frontend-types.ts` as a starting point, with `/openapi.json` authoritative. Keep backend logic in Satvik's code. Arjun owns the investigation layout, playback controls, visual timeline, evidence cards, report presentation, and demo.

`backend/examples/constructed-sound-scene.wav` is a recorded-sound collage for integration. Upload with `{"is_simulated":true}` and leave motion assumptions false. Display “Constructed sound scene” prominently. It combines separate engine/horn/glass/siren excerpts; it does not record an actual crash. Credits and excerpt spans are in adjacent files. The trained clip classifier is separate from the API timeline; see `ML_MODEL_CARD.md`.

`backend/examples/example-sound-result.json` and `example-scene-scores.json` contain a successful live result for this collage. Generate local asset URLs by uploading the WAV; the checked-in response's analysis ID is not a portable server. With a running backend, `python scripts/smoke_sound_demo.py` verifies the upload and refreshes these examples.
